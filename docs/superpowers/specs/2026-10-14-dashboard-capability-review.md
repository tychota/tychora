## Authorization, browser admission and caching

- LocalAuth requires exact numeric loopback Host and Bearer token, same-origin Origin when present, unique security/control headers; X-Tychora-Scope can only narrow the token grant (`interfaces/http/auth.py:51-149`). Tokens share a single installation principal; no multi-user identity isolation. UI collection selection should narrow via the granted scope, not client-side filtering as authorization.
- Discovery/source/inspect/query need read; source mutation/retry need write; settings/evaluations/most maintenance need manage. Job get/cancel/events use durable job authorization (not just route capability checks). Health needs whole-workspace proof. Missing/inaccessible behavior is operation-specific; do not promise identical HTTP 404 everywhere.
- ErrorEnvelope has schema_version,code,message,retryable,run_or_job_id,diagnostic_refs; there is no permitted-next-action field. Display actual typed errors and preserve input.
- SSE explicitly emits Cache-Control:no-store. Other API/artifact responses do not currently emit blanket no-store headers. Browser client should use cache:no-store, avoid local persistence of query/original payloads, and never put bearer credentials in URLs.
- FastAPI docs/OpenAPI are disabled; raw boundary currently authenticates every HTTP route. Bundled dashboard shell requires an explicit public-static/authenticated-data admission decision. Native EventSource cannot attach Bearer headers; use fetch-based SSE parsing (or a deliberate same-origin session design), not token query parameters.

## Smallest useful backend changes

1. Fix evaluation list/detail serialization and add real HTTP read-contract tests; prefer bounded/versioned typed DTOs. Do not let broken reads appear as empty evaluations.
2. Add scoped collection definitions only if labeled selection is required; initial single workspace/granted ID selector can ship without global registry.
3. Add a scoped revision/source metadata DTO (title, actual dates/capture time, source hash, active membership, extraction identity) and bounded revision evidence/asset inventory for browsing beyond search hits. Never infer current revision by sort order.
4. Add safe query-run metadata projection for fields already persisted (metrics/epochs/config/evidence IDs); defer trace/full-retention/purge/analytics UI until genuine backend implementation and permission tests exist.
5. Add assertion detail and code-context locator/reason only for richer explanation requirements. Existing bounded edge list/search citation inspection is usable now.
6. Keep representation settings explicitly incompatible on indexed workspaces unless an accepted transactional rebuild workflow is implemented. Do not present the draft's automatic rebuild promise.

The dashboard can implement Search, scoped Sources, Jobs, metadata-only Activity, saved evaluation reports after the read fix, and redacted Settings against real HTTP. Missing features should have accurate unavailable states or be omitted until their backend work is accepted.
