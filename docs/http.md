# Local HTTP API

The optional `server` dependencies expose one versioned API for an opened workspace. The host entry point is `python -m tychora.interfaces.http.server WORKSPACE [--port PORT]`; it binds one Uvicorn worker to `127.0.0.1` and publishes the bound authority in the private `.runtime/endpoint.json` record. `connect_local(WORKSPACE)` verifies that record, the live owner lock, the workspace UUID, protocol version, and the HTTP handshake before returning a blocking client. `Tychora.connect(endpoint, credential, workspace_id)` and `AsyncTychora.connect(endpoint, credential, workspace_id)` are the explicit credentialed client constructors; the async client verifies its handshake before its first operation. A stale record or a different endpoint identity fails closed. The runtime record contains a bearer secret, so its directory and file must remain owner-only. Credentials are sent in `Authorization`, never in URLs.

`create_app(owner, services, auth)` borrows an already-open owner. Its FastAPI lifespan drains the **current** service binding's accepted source jobs. The server context owns final owner closure, with a fallback drain if startup or shutdown fails. A later settings activation replaces the authoritative `app.state.runtime.services` binding; consumers should look it up per request instead of retaining the original container. Any embedded transport sharing this owner must use the runtime admission gate for operations and settings activation; it must not drive a retained `Services` object independently. The host is a local, single-installation-principal service. Separate bearer tokens may have narrower collection, use, read, write, and manage grants; every operation intersects the token grant with the owner's scope and any per-request `X-Tychora-Scope`. Tokens naming a different principal are rejected. Same-principal tokens share that principal's history and idempotency namespace, subject to each token's effective scope and the durable job authorization receipt. This is not multi-user identity isolation.

Every request needs exactly one `Host` equal to the bound numeric loopback authority and exactly one `Authorization: Bearer …`. Native clients may omit `Origin`; when present, exactly one Origin must equal `http://` plus that authority. Duplicate control headers are rejected before route parsing. Actual incoming body bytes are limited to 1 MiB, including requests without `Content-Length`; malformed or oversized length is rejected before body parsing. No wildcard CORS or remote bind is configured. Source paths require write scope and must resolve within configured ingest roots. A request's response or resource-specific bounds may be smaller.

The API returns schema-versioned canonical error envelopes containing `code`, sanitized `message`, and `retryable`; envelopes are under 8 KiB. Invalid requests and budgets use HTTP 400, scope denial 403, missing resources 404, busy/profile/idempotency conflicts 409, removed original 410, unsupported media 406, unavailable capability/index/provider 503, and deadlines 504.

| Route | Contract |
| --- | --- |
| `GET /v1/handshake` | Protocol, workspace and instance identities, effective token scope, and accessible default collection ID. |
| `GET /v1/discovery[/{subject}]` | Scoped, cursor-bounded definitions, counts, and capabilities. Subjects include kinds, facets, relations, profiles, languages, sources, settings, runs, and models. |
| `POST /v1/sources`; `GET /v1/sources[/{id}]`; `GET /v1/sources/{id}/revisions`; `POST /v1/sources/{id}/sync` | Source registration and source-specific sync need `write`; accepted operations return HTTP 202 with a durable `JobHandle`. Read routes expose scoped retained metadata and revisions. Source input uses a UUID collection ID and registered kind such as `manual@1`; the literal `default` resolves only when that collection is granted. |
| `GET /v1/evidence/{id}`; `GET /v1/assets/{id}`; `GET /v1/assets/{id}/content`; `POST /v1/relations` | Scoped bounded inspection; asset bytes come only from registered asset bindings. |
| `POST /v1/queries`; `GET /v1/queries[/{id}]`; `POST /v1/queries/{id}/replay` | Query execution and scoped retained history. Search returns the verified response assembler bytes. The default `Accept: application/json` uses canonical JSON; `application/vnd.tychora.hierarchical+json` selects the hierarchical projection. Unsupported media returns 406. Default metadata-only history cannot replay a request body and returns `REPLAY_UNAVAILABLE` (409). |
| `GET /v1/jobs[/{id}]`; `POST /v1/jobs/{id}/cancel`; `POST /v1/jobs/{id}/retry`; `GET /v1/jobs/{id}/events` | Scoped durable status and control. Cancel authorization is durable before the local worker is signaled. SSE `Last-Event-ID` resumes at strictly greater sequence; expiration emits `refresh`, requiring a status read. Stream disconnect does not cancel the job. |
| `POST /v1/jobs`; `/v1/evaluations` | Typed maintenance and evaluation entry points currently report `CAPABILITY_MISSING` (503) after scope and request validation; their application services arrive in later tasks. Generic maintenance sync remains `manage`, while source-specific sync is `write`. |
| `GET /v1/settings`; `PUT /v1/settings` | GET returns redacted effective settings. PUT needs `manage` and exactly `{ "profile": "…", "workspace_toml": "…" }`, with no unknown fields; secrets remain references in TOML. |

`Idempotency-Key` binds canonical source intent. Duplicate pending submissions return the same durable handle and share one execution; a conflicting intent returns 409. Accepted workers run on the owner's source-job loop independently of the HTTP connection. `GET /v1/jobs/{id}/events` is a reconnectable view of durable events, not a separate execution queue.

Settings activation is exclusive with admitted HTTP requests and active accepted source jobs. It validates a candidate configuration, including every retained kind in declared collections, and prepares replacement ports inside that exclusive gate. Service constructors require the owner's canonical ports, so preparation temporarily binds the candidate on the owner thread and restores the previous binding in `finally` before any new HTTP admission. On success it bumps `policy_epoch` for a changed configuration, atomically replaces `workspace.toml`, then swaps the in-memory owner/store/service binding and drains the old source bridge. Invalid or incompatible candidates preserve the previous effective configuration; busy work receives `WORKSPACE_BUSY`. A crash before file replacement may leave an extra epoch invalidation but keeps the old settings file. A crash after replacement recovers the new file on restart; file replacement and the database epoch are not one cross-store transaction. Existing index generations are never reinterpreted under a changed index fingerprint. No provider call or download occurs during activation.

This module supplies the reusable delegation handshake and host entry point. Public daily CLI commands, including owner-busy command behavior, are implemented by the later CLI task; MCP sessions also consume the current service binding and close before the app's job drain.
