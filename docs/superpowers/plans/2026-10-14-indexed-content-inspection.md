# Indexed Content Inspection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make exact returned passages, stored retrieval chunks and extracted units readable from Search and Sources.

**Architecture:** Add scoped, bounded retained-content inspection in the existing application service and expose two lineage HTTP reads. The dashboard consumes authoritative window text and separates returned passage, stored chunk and full-unit presentation.

**Tech Stack:** Existing Python/SQLite/FastAPI and React/TypeScript/Vitest/Playwright; no new runtime dependency.

**Spec:** `docs/superpowers/specs/2026-10-14-indexed-content-inspection-design.md`.

## Global Constraints

- Default page20, maximum50; response budget1MiB.
- All API requests remain bearer/scope bound with retained inspection authorization and delivery-time policy revalidation.
- Never regenerate chunks, invent tokenizer identity, or call stored rows active snapshot membership without proof.
- Render server-provided exact text; no JavaScript slicing using Python codepoint offsets.
- Keep quiet, dense, warm styling; raw JSON remains optional diagnostics.
- Preserve running preview data, other worktrees and verification records; no live providers.
- Real user document bytes/text/paths must not enter committed fixtures.

## Review Focus

- Clipped query anchor vs larger stored window: resolving the stored ID must show full stored bounds/text, not the clipped excerpt.
- Non-BMP Unicode/combining characters: exact server text survives UI rendering without UTF-16 offset corruption.
- Denied overlapping children: no hidden text/identity/hash/length leaks; authorized disjoint ranges remain readable.
- Changed scope/lineage/filter/cursor: reject stale or foreign continuation and isolate in-flight UI data.
- Removed originals, retained historic chunks and structured-only segments: honest readability/completeness without false active-index claims.
