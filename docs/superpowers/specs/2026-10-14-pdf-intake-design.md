# PDF intake, analysis, and local OCR design

Status: reviewable draft. Browser file picking is the selected default. Execution remains the previously selected subagent-driven workflow. The user has authorized local analysis followed by ingestion of their supplied document; concrete implementation review, backup and verification are technical sequencing gates, not new permission requests.

## Outcome and evidence

A person chooses a PDF, receives a local structural analysis, reviews the required processing and destination, and submits the same immutable original into the existing source job. A 382-page, approximately 50 MiB image-only book was inspected locally: no page had extractable text. A private one-page probe established that pinned RapidOCR with PDFium rendering produces mapped text and physical page geometry. The existing threaded renderer introduced raster-strip seams and classified the prose page as a table; the PDFium comparison removed both artifacts. Recognition missed one checked name and interleaved marginal content, so neither perfect transcription nor full-document resource coverage is established. The user's original, text, filename, absolute path, and probe output must never become committed examples or fixtures.

The current dashboard converts chosen files to base64 inside a 1 MiB JSON request; BytesSource also has a 10 MiB inline acquisition ceiling. Raising JSON limits would retain buffering and still fail a large PDF. Current Docling disables OCR. Local region OCR is available but requires explicit caller regions and accepts at most 100 selections. Intake must solve binary transport, analysis, durable capture, and explicit OCR provenance together.

## Global constraints

- Upload bytes are capped at min(104857600, current configured max_file_bytes, current configured max_total_bytes); ordinary JSON remains capped at 1048576 bytes.
- PDF processing uses installed pinned dependencies and verified local assets only; no remote fallback, provider upload, model download, dependency installation, or provider activation.
- Every intake is bound to workspace, principal, effective grant, collection, canonical logical descriptor, original SHA-256, analysis identity, and resolved PDF processing policy.
- Original bytes and revision identity are immutable; OCR changes extraction identity and remains text_origin=ocr, citable=false, review_state=needs_review with source-pixel dependencies and derivation receipts.
- Existing native parsing behavior, workspace profile, configuration identity, and index generations remain intact; the PDF parser is explicitly selected per intake.
- Existing caps remain: 40 million pixels per image/canvas/mask, 100000 mapped/preflight items, 256 MiB parser output per child collection, 256 MiB aggregate parser metadata, 16 MiB retained extraction/composition manifest, 1 GiB default CAS object ceiling.
- The new processing aggregate budget is 1 GiB for original plus derived artifacts, narrowed only by an explicit lower owner processing budget; streaming counted enforcement precedes retention. Acquisition max_file_bytes/max_total_bytes bound input originals and sidecars, not derived OCR artifacts. This is a new aggregate quota, not the existing CAS per-object ceiling.
- Synthetic fixtures only; no user-document bytes, transcriptions, filename, or absolute path in committed docs, tests, fixtures, or logs.
- The current preview on port 8767 and its data remain untouched until an explicitly reviewed migration/deployment step.

## Browser and HTTP flow

The user has now requested a unified dashboard redesign with one workspace, multiple collections and full administration. This PDF delivery owns the backend interfaces and the UI acceptance contract; the forthcoming unified dashboard plan owns the single final file-picker/analysis/review implementation. Do not build a competing temporary source form.

1. Prepare an intake with a small JSON request: logical source key, collection, qualified kind, metadata, PDF format, and expected byte count. A filename is optional display text, never a server path. The owner checks write capability, collection visibility, metadata/kind eligibility and budgets before issuing a cryptographically random opaque receipt.
2. PUT the File as application/pdf or application/octet-stream to the receipt's content endpoint. Authenticate Host/Origin/token/grant and reject excessive declared length before requesting any body. Count every received chunk, including chunked requests, and spool into private mode-0600 staging. Do not base64-encode or call File.arrayBuffer in the dashboard. A mismatched known length, disconnect, overrun, changed scope, or failed fsync aborts the intake.
3. Analyze the completed immutable file locally. Structural inspection reports page count, pages with native text, image pages, unreadable/encrypted status, and requires_ocr. All pages are counted; classification cannot rely on the cover. Analysis includes typed capability blockers, qualified normalizer/default parser information, and a proposed native or local OCR policy. Native text PDFs preserve the current PDF adapter; scanned pages explicitly select PDFium and full-page pinned local RapidOCR.
4. The user reviews file size/page count, scanned or mixed classification, destination, required local OCR, accuracy limitations and capability blockers. They confirm that exact analysis and policy. No source job starts during upload or census. Unknown/unreadable pages and mixed-page classification remain visible.
5. Submit the analysis identity with an idempotency key. Recheck scope/config compatibility and immutable bytes, promote the original into CAS, create trusted acquisition input, then use the existing SourceJobScheduler and SourceService. Show the JobHandle, persisted capture/parse/projection stages, and eventual source/revision/extraction coverage; queued or staged never means ingested.

Routes are POST /v1/pdf-intakes, PUT /v1/pdf-intakes/{intake_id}/content, GET /v1/pdf-intakes/{intake_id}, POST /v1/pdf-intakes/{intake_id}/analyse, POST /v1/pdf-intakes/{intake_id}/submit, DELETE /v1/pdf-intakes/{intake_id}. Except the exact authenticated PUT content route, the existing RawBoundary and JSON limit apply. API responses never expose staging paths, CAS storage keys, credentials, or private receipt bindings. Cross-owner/principal/collection/receipt mismatches are denied before opening content. Admission remains inside ServiceRuntime's activation gate.

## Service contracts and ownership

Create independent contracts/pdf_policy.py for PdfProcessingPolicy, contracts/pdf_intake.py for PdfIntakeDescriptor, PdfIntakeStatus, PdfAnalysis and PdfIntakeSubmission, and application/acquired_source.py for the internal AcquiredSource binding. requests.py imports only pdf_policy.py; public policy contracts never import requests.py. The private acquisition seam uses future annotations and TYPE_CHECKING for request/source types, avoiding a circular runtime import. Create application/pdf_intake.py for PdfIntakeService and private receipt lifecycle; ingestion/pdf_analysis.py for pure structural classification; interfaces/http/pdf_intakes.py for HTTP composition. SourceJobScheduler remains the sole background source-job loop.

Receipt states are prepared, receiving, staged, analysing, analysed, submitted, aborted, expired, failed. Receipts live under the owner's private intake directory; atomic mode-0600 records bind an unpredictable ID to owner/grant/descriptor/config/expiry and a generated internal original filename. Names supplied by users never determine a directory entry. Finalized bytes cannot be overwritten. Repeated successful PUT of the same completed receipt is rejected; interrupted receives are aborted and need a fresh preparation. Submit retry returns the same accepted job. Persist the submit handoff before deleting staging; recovery must reconcile a job accepted before the response rather than create a second job.

Proposed finite intake defaults are four outstanding receipts per principal, eight per owner, 512 MiB aggregate staged/reserved bytes per owner, a 30-minute unsubmitted TTL, one analysis process per owner, 60-second analysis wall limit, and 60-second upload idle timeout. Reserve expected bytes before receive; current lower acquisition ceilings still win. Expiration and abort release reservations and unlink private files after workers exit. Startup sweeps incomplete/expired receipts using no-follow/regular-file checks. A submitted receipt retains only the durable job binding; CAS cleanup uses existing artifact ownership/pinning rather than a new arbitrary-delete path.

An UploadSource variant has a logical descriptor plus received content_sha256 and size_bytes, with no byte payload, filesystem path, or public arbitrary-artifact read. Ordinary sources.add refuses it without a trusted acquired binding; only PdfIntakeService can resolve a receipt and produce that binding. Acquirer.capture_acquired constructs the existing CaptureManifest using canonical source metadata and existing _manifest logic. SourceService.execute_accepted persists jobs.capture before invoking any parser. Retry rehydrates the small UploadSource descriptor from retained capture, never reads/base64-encodes the entire original. Sync of an upload explicitly reuses its retained immutable original, or the user creates a new upload for changed content. CAS pinning spans promotion through persisted capture ownership.

## Explicit per-intake PDF policy

Add an optional pdf_processing policy to SourceBase. Absence preserves existing source serialization, request digests, capture descriptors, fingerprints and default parser behavior byte-for-byte; do not add a serialized null to old inputs. A reviewed policy records parser=docling, version=pdf-processing@1, native or local_ocr mode, page selection/mode, backend, image and OCR scales, verified runtime/model inventory identities, processing bounds and blank-page handling. Users select a server-proposed policy; they cannot provide arbitrary backend classes, model paths or RapidOCR parameters.

DoclingParser._prepare accepts explicit PDF policy after qualification even if the workspace default parser is markdown. Source registration already dispatches pdf to DocumentRegistration; the scoped policy supplies the qualified adapter without changing owner.config, SettingsService.activate or indexed_representation_identity. Capture stores the policy; parser fingerprint includes every effective backend/OCR/model/runtime option. Retained replay revalidates policy/origin/receipt binding; retries use the accepted policy and cannot silently adopt updated settings or models. Existing no-policy native extractions retain their legacy fingerprint and replay support. Registry kind/normalizer eligibility remains checked; a missing document capability yields CAPABILITY_MISSING with explicit prerequisites, rather than a silent profile mutation.

For image-only pages use PdfFormatOption(backend=PyPdfiumDocumentBackend) and PdfPipelineOptions(do_ocr=True, ocr_options=RapidOcrOptions(backend=onnxruntime, mode=OcrMode.FULL_PAGE, det_model_path=verified_detection, rec_model_path=verified_recognition, cls_model_path=verified_classification, scale=3.0)). Keep local artifacts_path, CPU two threads, remote services/plugins disabled, offline flags and telemetry disabled before import. Cached models are the verified pinned inventory, not an assumed alternate language download. Native/mixed PDFs need a recorded per-page native-versus-OCR plan: retain native page text, run full-page OCR only for explicitly selected scanned pages, and never overwrite native text with OCR. PDFium is selected for scanned page passes; the existing backend remains the native pass.

## OCR origin and retained evidence

Enable generate_parsed_pages=True in OCR passes, inspect TextCell.from_ocr before SDK cleanup, and write a canonical per-page OCR sidecar containing native/ocr cell markers, cell text and scores, PDF-point rectangles, rendered pixel geometry, original/page/region hashes, model/runtime/policy identities and page coverage. In scan passes retain the exact OCR input raster at scale 3.0 as an external image artifact, with pixel equality verified at the SDK boundary, so the existing crop/region proof refers to the actual model input. A measured sampled-page raster is 665480 PNG bytes; 382 identical pages would use about 242.44 MiB PNG or 323.25 MiB base64 before metadata. This one-page estimate motivates avoiding base64 and is not a full-document byte forecast. The one-page feasibility probe retained scale-1 display images; the later size measurement did not run OCR, so exact scale-3 provenance/full-document budgets remain qualification work. Native passes keep their prior scale-1 assets; no unsupported upscale proof is invented. Text origin is not guessed from nonempty SDK text or the PDF filename. An OCR page with native cells or ambiguous item-to-cell binding fails INTEGRITY_ERROR rather than being relabeled as native.

The existing complete Docling JSON and DocumentUnit mapping remain retained parser facts. Add origin metadata to DocumentUnit and validate it against the retained sidecar and original page. Native units continue through existing native document normalizers; OCR units are excluded from native source-text/caption/record manufacture. Preserve layout items and geometry as derived facts. Reconcile all validators and replay paths: validate_document_units currently binds every mapped unit to complete JSON, so deleting OCR units from the retained mapped tuple is invalid.

Compose OCR page/region transcripts through planned_vision_proxy, PlannedRegion and ProxyFactory, with a receipt renderer matching the existing vision_derivation checks. Original page pixels become source-owner units through _materialize_pixel_source_view. OCR proxies remain review-required and depend on those pixels; model scores do not promote citable status. Create deterministic source-owner units and same-extraction page assets/locators before ProxyFactory construction. The dashboard shows indexed OCR separately and states whether the current query review filters include needs_review OCR; it never auto-accepts a transcription to make search succeed. Define a shared local receipt builder for LocalOcrProvider and the Docling sidecar so receipt schemas/cache identity stay identical. No second OCR run is needed merely to manufacture provenance. Existing reading order is retained and identified as parser-derived; it is not claimed to be perfect. Tables recognized by OCR stay derived; a special record normalizer cannot assert native table facts from them.

## Bounded conversion and failures

Structural analysis accepts at most 1000 pages and existing image/object caps. Initial full OCR execution defaults to at most 5400 seconds overall, 120 seconds SDK time per processing batch, 180 seconds child wall time per batch, CPU two threads, and batch/queue values 1/2. Start with 16-page passes, reusing loaded models only within a bounded child lifetime. Use a bounded merge_pdf_page_exports helper over completed 16-page exports: remap each batch's item self_ref/$ref array offsets and hierarchy links, preserve root body/furniture order, preserve original pages dictionary keys and every provenance page_no unchanged, reject duplicate pages or unsupported reference domains, and require validate_document_units to bind the merged result. Do not use DoclingDocument.concatenate because it can shift physical pages. Exports merge under aggregate metadata/memory budgets; exact image artifacts are flushed and verified in bounded child output batches, and parsed/raster intermediates are released after verified transfer. Loaded models are reused across bounded page passes with observable job page progress. No paged document manifest format is introduced. The explicit scan-external-images@1 representation externalizes exact OCR PNG pixels as manifest-declared image ArtifactRefs instead of embedding base64 into merged Docling JSON. Its version lives in the retained extraction envelope and image bindings sidecar. The retained image uri uses urn:tychora:artifact:sha256:<digest>; a native_ref-to-ArtifactRef sidecar binds that identifier to a declared asset. This URI is an identity, never a fetchable location. The scan validator accepts it only under that explicit version and verifies the declared exact payload; native legacy validation continues to require embedded data URLs. Legacy native embedded-image validation remains intact. The owner collector counts each streamed batch before retaining it: 256 MiB per child collection, 256 MiB aggregate metadata, and a new 1 GiB aggregate original-plus-derived processing quota, narrowed by an explicit lower owner processing budget. Acquisition max_file_bytes/max_total_bytes still apply to the input original and sidecars only; do not incorrectly apply their input-only bound to derived images. PdfIntakeService accepts max_retained_bytes=1073741824 at its owner composition boundary and captures that budget into the policy; callers cannot raise it. Existing CAS 1 GiB is a per-object bound, not a pre-existing aggregate quota. The retained extraction/composition budget stays 16 MiB. Each declared external image is validated by exact hash/size/media/dimensions/geometry through authorized pinned payloads; undeclared or arbitrary caller CAS references fail. Exceeding a limit fails with LIMIT_EXCEEDED and retains an unsuccessful job/capture, not a truncated success. Larger documents are offered an explicit later plan, not silently split into separate source identities.

The supervisor enforces wall deadlines and cancellation with terminate/reap before staging cleanup. Monitor child resident memory with a proposed 4 GiB threshold and bounded platform checks; this is a sampled cancellation threshold, not an OS-enforced hard memory guarantee. If reliable monitoring is unavailable on the platform, report CAPABILITY_MISSING for this bounded path. Repeated page passes must not accumulate full raster documents in process memory. SDK SUCCESS, no timeout/errors, and exact expected page coverage are mandatory; PARTIAL_SUCCESS is a failure. Missing models/runtime -> CAPABILITY_MISSING; invalid/encrypted/unreadable PDF -> INVALID_REQUEST; timeout -> DEADLINE_EXCEEDED; capacity -> LIMIT_EXCEEDED; stale analysis/config/scope -> SCOPE_CHANGED or IDEMPOTENCY_CONFLICT. Unknown error details remain sanitized at the child boundary.

An all-image page may genuinely be blank or graphical. Structural analysis distinguishes known blank pages from image-only and unknown pages; image presence does not prove text is present. A processed image-only page with no detected text retains an explicit no-text-detected coverage diagnostic and its page pixels, never an invented blank-page assertion. Detected text that produces no usable transcription, or an unreadable/failed page, fails INDEX_INCOMPLETE. A fully processed document with usable text on other pages may publish with explicit coverage gaps; its status is indexed with gaps, not complete transcription. A source with no usable text is not presented as ready/searchable. Partial availability is explicitly reported in extraction/channel coverage.

## Load-bearing review questions

- The bounded merged export must pass complete JSON hierarchy/unit validators and the explicitly versioned external-image asset validator with original physical page numbers. Reject unsupported reference domains and capacity failure; a new paged manifest or identity-changing workaround is outside this plan.
- Mixed native/OCR origin mapping and derived table normalization require proof against parsed-cell markers; geometry overlap alone is not a qualified text-origin binding. Fail ambiguous binding rather than inventing native origin.
- Sampled RSS monitoring is not a hard memory sandbox. The platform implementation and thresholds need review before full-book execution.
- Per-intake policy must be reconciled with pinned config compatibility, source sync, projection chunk identity, restore and extraction replay; default config stability alone is insufficient.
